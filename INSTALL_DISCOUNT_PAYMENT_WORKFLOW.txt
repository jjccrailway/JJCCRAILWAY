INSTALL ORDER
1. Back up your Supabase database.
2. In Supabase SQL Editor, run 15_discount_id_verification.sql.
3. Run 16_passenger_level_payment_workflow.sql.
4. If pg_cron is enabled (or after enabling it in Database > Extensions), run
   17_schedule_passenger_expiry.sql. This is required for automatic release of only
   the passenger seat whose 10-minute payment window expires.
5. Deploy the HTML/JS files to the same website root, preserving the existing
   folder structure. Do not delete the existing 01–14 SQL migration files.

WORKFLOW INCLUDED
- Passenger types: Regular, Student, Senior Citizen, PWD.
- Student/Senior/PWD ID uploads: JPG, JPEG, PNG, WEBP, PDF; maximum 5 MB.
- ID-pending passengers have no automatic expiry.
- Admin and Superadmin can approve/reject IDs.
- Approval applies 20%; rejection changes the passenger to Regular and recalculates the fare.
- The 10-minute payment deadline begins per passenger when the ID decision notification is created.
- Regular passengers can pay while discounted passengers await ID verification.
- Passenger receipts and JCoins are tracked per passenger.
- A submitted receipt remains pending until an Admin/Superadmin reviews it; review delay does not expire the seat.
- If one passenger misses their payment deadline, only that passenger's outbound and return seat links are released.
- JCoins are returned if a receipt is rejected or a passenger payment hold expires after a partial JCoins debit.
- Legacy bookings without the new workflow flag are redirected to legacy-payment.html.
